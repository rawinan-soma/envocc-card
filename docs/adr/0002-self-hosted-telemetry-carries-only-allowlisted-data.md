# Telemetry is self-hosted in its own stack and carries only allowlisted data

Metrics, traces and logs are instrumented with OpenTelemetry and shipped to a self-hosted stack (Collector, Prometheus, Tempo, Loki, Grafana) that runs as its own Compose project beside the api, not inside it, and is reached only over a VPN (Tailscale on the pilot server). We chose this over a hosted service because the system holds applicants' personal data, and sending any of it to a third party, usually abroad, raises PDPA and agency-policy problems; a separate project keeps telemetry alive when the app is redeployed, taken down or reset, which is exactly when it's needed. For the same reason telemetry carries only an allowlist: internal ids, routes, status codes, error types, Request Status numbers and organization codes — never request bodies, headers, cookies, query values, names, emails or tokens — with the Collector redacting emails, JWTs and 13-digit ID numbers as a backstop rather than as the main defence. The cost is a stack to operate ourselves and logs that are deliberately sparse when debugging. Don't "fix" this by logging a request body or a user's name to chase a bug, or by pointing the exporter at a SaaS, without revisiting the decision.
